# 现在就出发（前端）PRD

- 文档版本：v1.0
- 更新时间：2026-05-22
- 适用范围：`frontend`（React + TypeScript + Vite）
- 产品阶段：Hackathon MVP 向可落地产品演进

---

## 1. 背景与目标

### 1.1 背景
用户在本地游/周末游决策中面临三个核心问题：

1. 信息碎片化：需要跨平台收集信息，决策成本高。
2. 路线串联难：多个 POI 的顺序、时长、预算、排队无法快速平衡。
3. 执行断层：拿到方案后缺少后续执行与沉淀（保存、复用、复盘）。

### 1.2 产品目标
打造“自然语言输入 -> 自动规划 -> 可编辑 -> 可执行 -> 可复用”的完整闭环。

### 1.3 核心成功指标（阶段性）

- 路线生成成功率 >= 90%
- 首次会话后出方案率 >= 80%
- 方案保存到“我的行程”转化率 >= 40%
- 生成后触发“开始出发/继续执行”比例 >= 30%
- 用户反馈提交率 >= 25%

## 2. 用户与场景

### 2.1 目标用户

- 城市白领（周末半日游）
- 亲子家庭（带娃出行）
- 情侣/朋友聚会（社交目的）

### 2.2 典型场景

- 模糊意图："周末想出去走走，不知道去哪"
- 明确约束："上海半天 citywalk，2 人，预算 200，少排队"
- 行中变化："堵车了" / "太累了" / "排队太久"

---

## 3. 产品范围与版本定义

## 3.1 版本拆分

- V0（当前）：Onboarding + 对话 + 出方案 + 基础重规划 + 反馈
- V1（MVP 目标）：补齐“我的行程”与执行闭环，提升容错与一致性
- V2：增强可编辑、地图、分享、预约等能力
- V3：实时监控、历史偏好建模、多人协同

## 3.2 MVP（V1）定义

### 必须包含（In Scope）

1. Onboarding 画像收集（3 步）
2. 对话式路线生成（支持追问）
3. 2-3 条路线对比展示（含评分维度）
4. ActionBar 重规划（换一家/省钱/少排队/亲子）
5. 突发事件重规划（排队/堵车/疲惫）
6. “保存路线”能力
7. “我的行程”列表页（待出发/进行中/已完成）
8. 行程详情页（查看节点、继续规划、开始出发、完成行程）
9. 反馈提交并真实生效（权重更新可落库）
10. 关键容错（网络失败、无结果、参数缺失、数据损坏）

### 不在 MVP（Out of Scope）

1. 地图拖拽编辑
2. 实时交通/营业状态订阅推送
3. 一键预约真实链路
4. 跨设备云同步（可先本地）
5. 多人协同编辑

---

## 4. 端到端用户流程（目标态）

1. 首次进入 -> 填写画像（场景/偏好/预算/城市）
2. 进入 Planner -> 输入需求或点击快捷词
3. 系统生成路线（必要时追问）
4. 用户查看并编辑方案（ActionBar/重规划）
5. 用户点击“保存到我的行程”
6. 在“我的行程”中管理状态：待出发 -> 进行中 -> 已完成
7. 完成后提交反馈，优化后续推荐

## 6. MVP 详细需求（V1）

## 6.1 画像引导（Onboarding）

### 功能说明
- Step1：出行场景多选（>=1）
- Step2：偏好标签（>=1）+ 避开标签
- Step3：预算 + 城市 + 昵称

### 验收标准
- 可完成 3 步并进入 Planner
- 刷新后保留画像
- localStorage 脏数据可自动回退默认值，不白屏

### 异常兜底
- `loadProfile` 解析失败 -> 清空并回退默认 profile

## 6.2 对话规划与追问

### 功能说明
- 输入自然语言后发送请求
- 显示用户/助手消息气泡
- 若需补信息，显示追问卡片与快捷回答

### 验收标准
- 发送-响应-渲染链路完整
- loading 与 error 展示正确

### 异常兜底
- 请求失败可重试
- 无路线时给“建议改写问题”与示例 chips

## 6.3 路线结果展示

### 功能说明
- 展示 2-3 条路线（横向切换）
- 每条展示：摘要、时长、预算、排队、评分、时间线、推荐原因

### 验收标准
- 卡片可切换
- 评分拆解显示正确（兼容 0-1 与 0-10）

## 6.4 重规划能力

### 功能说明
- ActionBar：4 个快捷改写意图
- ReplanPanel：3 个突发事件

### 验收标准
- 任一操作均可触发新一轮规划
- 新路线可替换旧路线展示

### 异常兜底
- loading 中禁用二次触发，避免并发竞态

## 6.5 保存路线与“我的行程”（新增）

### 功能说明

1. 路线卡增加“保存到我的行程”按钮
2. 新增“我的行程”入口（顶部按钮或底部导航）
3. 行程列表按状态展示：
   - 待出发（planned）
   - 进行中（ongoing）
   - 已完成（completed）
4. 行程详情支持：
   - 继续规划（带入原约束）
   - 开始出发（状态切换到进行中）
   - 标记完成（进入已完成）
   - 删除行程

### MVP 存储策略
- 优先本地持久化（localStorage）
- 后续可切换后端 API（保持数据模型一致）

### 验收标准
- 保存后在“我的行程”可见
- 状态变更实时生效
- 刷新后数据不丢

## 6.6 反馈学习闭环（修复项）

### 问题
当前存在“提交反馈后权重被重算覆盖”的风险。

### 需求
- `updateProfile` 支持“基础权重 + patch 合并”，不覆盖反馈 patch
- 反馈后下一次请求必须使用最新 profile

### 验收标准
- 提交反馈后权重字段发生可见变化
- 下一次聊天请求 payload 带新权重

## 9. 容错与降级策略

1. 网络失败：显示错误 toast + 重试按钮
2. 超时：提示“网络较慢，继续等待/重试”
3. 空结果：展示候选建议（热门区域/改写示例）
4. 并发点击：loading 阶段禁用 ActionBar/Replan 触发
5. 数据脏值：profile/trips 读取失败自动回退默认值
6. 会话隔离：session_id 不使用固定值，按会话生成并持久化
7. 兼容后端不可用：保留 `USE_MOCK` 环境开关

## 12. 验收清单（MVP）

1. 用户从 Onboarding 到出方案可完整跑通
2. 至少 2 条路线可展示和切换
3. 可触发 2 种以上重规划入口（ActionBar + 事件）
4. 路线可保存到“我的行程”并持久化
5. 行程状态可在 planned -> ongoing -> completed 流转
6. 反馈提交后，下次请求携带更新后的权重
7. 异常场景（失败/空结果/脏数据）不白屏

---

## 13. 已知风险与依赖

- 后端接口字段稳定性（`ChatResponse`、重规划返回结构）
- 实时数据可用性（排队/营业状态）
- 本地存储容量与多设备不一致（MVP 可接受）
- Hackathon 时间窗口有限，建议优先“可演示闭环”而非全量能力

---

## 14. 本 PRD 的实施优先顺序（最终版）

### 第一优先（立刻做）

1. 我的行程（保存 + 列表 + 状态）
2. 反馈学习生效（修复覆盖问题）
3. 请求使用最新画像（消除前后不一致）
4. 并发保护与容错

### 第二优先（增强体验）

1. 行程执行态
2. 结果编辑（替换/删除/追加）
3. 方案可视化差异

### 第三优先（扩展能力）

1. 分享与预约
2. 地图与实时状态
3. 历史偏好与协同
