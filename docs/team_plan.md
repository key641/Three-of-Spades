# 三人分工与三周计划

## A 同学：Agent / 后端编排 / 用户画像

### 负责范围

- FastAPI 主接口 `/api/chat`
- LLM 接入与 provider 切换
- Agent 编排与 tool calling
- 用户意图理解
- 澄清追问
- 用户画像
- 策略权重生成
- 多轮对话状态
- 动态事件理解
- 反馈解析与画像更新
- 路线解释和 Agent trace

### 每周任务

| 周次 | 目标 | 具体任务 | 产出 |
| --- | --- | --- | --- |
| 第 1 周 | 跑通 Agent 到工具基础链路 | 搭 FastAPI；实现 `/api/chat`；接模型；定义 tool schema；解析用户意图；生成画像和策略权重；调用 B 的 POI/路线工具 | `/api/chat`、`Intent JSON`、`StrategyWeights`、Agent trace |
| 第 2 周 | 多轮交互和策略调整 | 支持换一家、更省钱、少排队、少走路；维护 session；根据用户指令更新权重；生成路线解释 | 多轮对话、调整指令解析、推荐解释 |
| 第 3 周前半 | 动态事件和反馈闭环 | 识别排队、堵车、下雨、累了；调用重规划；解析评分反馈并更新画像 | 动态事件处理、画像更新 |
| 第 3 周后半 | 测试和答辩 | 测典型 prompt；稳定 Agent；准备架构图和讲解 | 稳定 Demo、架构说明、答辩稿 |

## B 同学：POI 数据 / 路线策略工具

### 负责范围

- POI schema
- mock POI 和 UGC 标签
- POI 召回
- 路线生成
- 路线评分
- 多目标路线
- 局部替换
- 动态重规划
- 路线调参

### 每周任务

| 周次 | 目标 | 具体任务 | 产出 |
| --- | --- | --- | --- |
| 第 1 周 | 数据和基础路线工具 | 设计 POI schema；生成 50-80 条 POI；实现 POI 召回；实现一条基础路线；对齐 Route JSON | POI 数据、`search_pois()`、基础 `generate_route()` |
| 第 2 周 | 多目标路线和评分 | 设计评分公式；实现综合、少排队、省钱路线；输出评分拆解；支持局部替换 | `generate_routes()`、`score_route()`、`replace_poi()` |
| 第 3 周前半 | 动态重规划 | 排队、堵车、累了、下雨后保留已完成 POI，只调整后续路线 | `replan_route()`、重规划前后对比 |
| 第 3 周后半 | 调参和稳定 | 用 demo case 测试；修不合理路线；补数据；联调字段 | 稳定路线工具、测试 case |

## C 同学：React 前端 / UI / 体验

### 负责范围

- React 项目
- 聊天输入
- Agent trace 展示
- 路线卡片
- POI 时间线
- 多方案对比
- 交互按钮
- 动态事件模拟
- 重规划展示
- 评分反馈
- Demo 操作脚本

### 每周任务

| 周次 | 目标 | 具体任务 | 产出 |
| --- | --- | --- | --- |
| 第 1 周 | 前端基础展示 | 搭 React；实现聊天输入；接 `/api/chat`；展示路线卡片和时间线 | Web Demo 初版 |
| 第 2 周 | 多方案和交互体验 | 展示三条路线；实现按钮；展示 Agent trace；优化卡片层级 | 多方案页面、交互按钮 |
| 第 3 周前半 | 动态重规划和反馈 | 实现事件模拟按钮；展示重规划变化；实现评分反馈 | 动态事件、反馈组件 |
| 第 3 周后半 | 测试和演示 | 全流程联调；修 UI 状态；优化视觉；准备脚本 | 最终 Demo、演示脚本 |
