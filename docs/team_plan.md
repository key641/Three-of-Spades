### 重规划意图边界

重规划分两类，A 同学负责在意图层明确输出处理模式，B 同学按模式选择路线服务。

| 类型 | 判断标准 | 典型话术 | 后端处理 |
| --- | --- | --- | --- |
| 全量重规划 `full_replan` | 用户改变整体偏好或路线目标，需要重新生成一组候选方案 | 更省钱一点、少排队一点、少走路、亲子友好一点、整体不满意重新来 | 继承城市、人数、时间、预算等硬约束；更新偏好和避雷；重新召回 POI；调用 `RouteService.generate_routes()` |
| 局部重规划 `partial_replan` | 用户基本接受原路线，只想替换或调整其中一部分；原因可以是突发事件，也可以是不喜欢某家店 | 换一家、不喜欢这家、第二站换掉、这家太贵了、下雨了怎么办、临时堵车、餐厅排队 90 分钟、景点关门 | 读取当前路线；定位受影响 POI；保留未受影响点；调用 `ReplanService.replan()` 做局部替换和时间、交通、预算重算 |

边界原则：偏好变化走全量重规划；指向当前路线某个点或现实突发状态走局部重规划。例如“少排队一点”是全量重规划，“这家餐厅排队 90 分钟”是局部重规划。

### 用户画像维度

画像分两层维护：长期画像记录用户稳定偏好，本次行程要求只在当前 session 内影响路线，不默认写入长期画像。长期画像先按路线算法已经使用的维度扩展，避免字段只是展示、不参与规划。

| 画像维度 | 字段 | 对路线算法的影响 |
| --- | --- | --- |
| 显式偏好和避开项 | `preferences`、`tags`、`avoid_tags` | 参与 POI 文本匹配、路线偏好评分、避雷惩罚 |
| 五类策略权重 | `preference_weights` | 影响质量、排队、距离、预算、偏好五个评分维度 |
| 行为敏感度 | `budget_sensitivity`、`walking_tolerance`、`crowd_tolerance`、`schedule_tightness`、`novelty_preference`、`comfort_preference` | 转换为策略权重，例如怕排队会提高排队权重，走路耐受低会提高距离权重 |
| 品类偏好 | `category_preferences` | 影响 POI 召回排序，例如更偏博物馆、餐厅、咖啡、夜景 |
| 路线角色偏好 | `preferred_route_roles` | 影响路线结构，例如主活动、餐饮、休息、拍照点、交通锚点 |
| 体验标签偏好 | `preferred_experience_tags` | 影响 POI 体验匹配，例如文艺、小众、老字号、亲子、免费 |
| 时段和交通偏好 | `preferred_time_slots`、`preferred_transport_modes` | 影响营业时段、夜游、地铁/公交/打车等衔接倾向 |
| 历史行为 | `liked_poi_ids`、`disliked_poi_ids`、`skipped_categories`、`common_adjust_actions` | 喜欢过的 POI 加分，不喜欢或跳过的内容降权，也为后续反馈闭环留入口 |

当前 demo 已接入 JSON 运行时存储。前端首轮 onboarding 可以只传轻量偏好；后端会把 seed JSON 或 runtime JSON 中已有的细画像读出，并在 POI 召回排序和策略权重里生效。
